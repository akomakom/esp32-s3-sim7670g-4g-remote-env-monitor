# Mosquitto broker — mutual-TLS setup

Broker config + certificate tooling for the Rental Monitor's MQTT link. Runs in
Docker with `--net=host`. Two listeners:

| Port | Transport | Auth | Use |
|------|-----------|------|-----|
| `1883` | plaintext | anonymous | LAN / Home Assistant (unchanged) |
| `8883` | **TLS 1.2** | **mutual cert + username/password** | internet-facing device uplink |

The device connects to `MQTT_HOST:MQTT_PORT` = **`broker.example.com:8883`**
(from `include/config.h`). Forward **WAN `8883` → this host `8883`** on your
router. TLS validates the *hostname*, not the port, so the port translation is
fine — the server cert's SAN is `broker.example.com`.

```
files here
├── docker-compose.yml     # run the broker (host networking)
├── config/
│   ├── mosquitto.conf      # the two-listener config
│   └── passwd              # generated by gen-passwd.sh (git-ignored)
├── certs/                  # generated by gen-certs.sh (git-ignored)
│   ├── ca.crt  ca.key
│   ├── server.crt  server.key
│   └── client.crt  client.key
├── gen-certs.sh           # make CA + server + client certs
├── gen-passwd.sh          # make the password file (needs docker)
├── ha-bridge.py           # decode MessagePack data -> per-sensor JSON for HA
├── ha-mqtt.yaml           # Home Assistant MQTT sensor/binary_sensor config
└── test-publish.sh        # publish a test value over mutual TLS
```

`certs/`, `config/passwd`, `data/`, and `log/` are git-ignored — private keys and
passwords never get committed. The firmware's copy of the CA + client cert/key
lives in `include/secrets/ca_cert.h` (also git-ignored).

## 1. Certificates (already generated)

`gen-certs.sh` has produced a private CA plus a broker cert (CN/SAN
`broker.example.com`) and a device cert (CN `rental-mon-01`), all in `certs/`.
To regenerate the leaf certs later (keeps the existing CA so deployed devices
keep trusting the broker):

```bash
./gen-certs.sh
```

Override host/device without editing the script:

```bash
BROKER_HOST=broker.example.com DEVICE_ID=rental-mon-01 ./gen-certs.sh
```

Delete `certs/ca.*` first if you want to rotate the CA too (this invalidates all
existing device certs).

## 2. Firmware secrets (already wired)

The device's CA + client cert + key were written into the firmware secrets header:

```bash
./gen-certs.sh --header ../include/secrets/ca_cert.h
```

That header defines `MQTT_CA_CERT`, `MQTT_CLIENT_CERT`, and `MQTT_CLIENT_KEY`, so
`mqtt_transport.cpp` automatically enables mutual TLS. Rebuild + flash:

```bash
pio run -t upload
```

## 3. Deploy the broker (on the broker host)

Copy this `mosquitto/` directory to the broker machine, then:

```bash
# a) password file for the TLS listener (defaults to rental-mon-01 / change-me)
./gen-passwd.sh rental-mon-01 'your-strong-password'

# b) let the container's mosquitto user (uid 1883) read the private key
sudo chown 1883:1883 certs/server.key
chmod 600 certs/server.key

# c) start it
docker compose up -d
docker compose logs -f          # watch for "Opening ipv4 listen socket on port 8883"
```

If you change the password, set the **same value** in `MQTT_PASSWORD` (via
`config.h` or, better, `platformio.ini` `build_flags` to keep it out of git) and
reflash.

> **Not using compose?** The equivalent `docker run`:
> ```bash
> docker run -d --name mosquitto --restart unless-stopped --net=host \
>   -v "$PWD/config:/mosquitto/config" \
>   -v "$PWD/certs:/mosquitto/config/certs:ro" \
>   -v "$PWD/data:/mosquitto/data" \
>   -v "$PWD/log:/mosquitto/log" \
>   eclipse-mosquitto:2
> ```

## 4. Test the TLS listener

From any machine that can reach the broker (uses the generated client cert):

```bash
# subscribe over mutual TLS
mosquitto_sub -h broker.example.com -p 8883 \
  --cafile certs/ca.crt --cert certs/client.crt --key certs/client.key \
  -u rental-mon-01 -P 'your-strong-password' -t 'rental/#' -v

# publish a test message
mosquitto_pub -h broker.example.com -p 8883 \
  --cafile certs/ca.crt --cert certs/client.crt --key certs/client.key \
  -u rental-mon-01 -P 'your-strong-password' -t 'rental/test' -m hello
```

A missing/wrong client cert must be **rejected** (that proves mutual TLS is on):

```bash
mosquitto_pub -h broker.example.com -p 8883 --cafile certs/ca.crt \
  -u rental-mon-01 -P 'your-strong-password' -t 'rental/test' -m nope
# -> connection error (no client certificate)
```

Or use the helper (publishes a retained reading HA will also pick up):

```bash
MQTT_PASS='your-strong-password' ./test-publish.sh tub 38.5
# testing on the broker host itself:
MQTT_HOST=localhost MQTT_PORT=8883 MQTT_PASS='...' ./test-publish.sh crawl 12.3
```

## 5. Home Assistant

HA's MQTT integration can't decode the device's MessagePack `data` topic, so a
tiny bridge decodes it into per-sensor JSON that HA reads.

**a) Run the bridge.** It subscribes to `rental/+/data`, and for each reading
publishes retained JSON to `rental/<device>/sensor/<key>` (keys:
`crawl return supply outdoor garage tub`). The device **health** topic is already
JSON and needs no bridge.

Containerised to match your stack ([`compose.yaml`](compose.yaml) +
[`Dockerfile`](Dockerfile), both `network_mode: host`). Put the password in a
`.env` next to the compose file, then bring it up:

```bash
echo "RENTAL_MQTT_PASS=your-strong-password" > .env
docker compose -f compose.yaml up -d --build
docker compose -f compose.yaml logs -f rental-bridge   # watch it decode
```

Or fold the `rental-bridge:` service into your existing multi-service compose
(point `build:` at wherever you copied this dir, and drop the `depends_on` note).
It reuses the broker's cert dir read-only and connects to `localhost:8883`.

Prefer no container? It also runs standalone:

```bash
pip install paho-mqtt msgpack
MQTT_PASS='your-strong-password' ./ha-bridge.py
```

**b) Configure HA.** Point the HA **MQTT integration** at the broker over TLS
(Settings → Devices & Services → MQTT → broker `broker.example.com`, port `8883`,
username/password, and upload `ca.crt` + `client.crt` + `client.key`). Then merge
[`ha-mqtt.yaml`](ha-mqtt.yaml) into your `configuration.yaml` under the top-level
`mqtt:` key and restart HA.

It defines a temperature entity for all 6 sensors (+humidity, dew point and
absolute humidity for the 5 SHT40s; the hot tub is temp-only), plus health
diagnostics (signal, heap, uptime, battery, buffered records, bytes tx/rx,
operator, firmware, reset reason) and connectivity/mains binary sensors. All
entities use the health topic's `online` flag for availability.

> **Note on history:** HA's MQTT sensors timestamp values at *receive* time. The
> device backdates its own `t` for its buffered/outage history, but HA can't
> backfill a sensor's past — so a big buffer flush lands in HA at "now". The true
> capture time is still in each reading's `t` field if you need it downstream.

## Notes & gotchas

- **Clock:** TLS checks the cert validity window. The device sets its clock via
  NTP after the cellular link is up (before the first MQTT connect), so this is
  handled — but a wildly wrong broker/device clock will fail the handshake.
- **Cert lifetime:** CA and leaf certs are valid 10 years (the node is
  inaccessible; long-lived on purpose). Re-run `gen-certs.sh` before expiry.
- **Key permissions:** if the broker log says it can't read `server.key`, it's
  the uid-1883 ownership step in §3b.
- **1883 stays open on all interfaces** (your choice). It's plaintext and
  anonymous — keep it off the WAN; only forward `8883` to `8883`.
